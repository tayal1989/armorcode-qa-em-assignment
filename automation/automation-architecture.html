🛠️ Playwright Unified Runner

We consolidate API contract checks and end-to-end storefront transactions under a unified **TypeScript + Playwright** runtime, eliminating framework context-switching overhead.

  • **Single Runner Context**: Shared HTTP headers, cookies, and tokens between API/UI threads.
  • **Browser Project Matrix**: Native parallel execution on Chromium, Firefox, and WebKit.
  • **Embedded Trace Triggers**: Captures network logs, DOM snapshots, and console outputs.

⚡ Target Application Topology

The target application runs at `http://localhost:8080`, hosting a polyglot microservice graph (Go, Node.js, C#, C++, Ruby, PHP) integrated with a Valkey-cart cache backend.

  • **Next.js BFF Gateway**: Routes page requests and handles REST endpoints.
  • **Valkey Cart Storage**: Stores active cart session lists.
  • **gRPC Internal Grid**: Synchronous mesh connecting core services.

Test Execution Lifecycle & CI/CD Gates

To accelerate delivery velocity while preventing regressions, we implement progressive quality gates across the development lifecycle.

Progressive CI/CD Pipeline Gates

🔁 Fast Feedback Loop (Gate 2)

Executed automatically on every PR commit. Mocks heavy dependencies to maintain a **< 10 minute SLA** execution gate. Ensures developers obtain rapid status check signals without pipeline blockages.

🛡️ Deep Regression Validation (Gate 4)

Runs out-of-band nightly. Triggers the complete matrix of browser platforms and REST API contract checks. Runs **k6 load test configurations** to capture scalability benchmarks.

Automation Coverage Breakdown

We focus automation efforts where they yield the highest ROI, while intentionally managing risk for visual or chaotic system behaviors.

Scope Automation Ratio

🟢 Automated Core Paths (85%)

Predicable, state-driven user interactions and REST contracts are fully automated:

  • **UI E2E Purchasing Flow**: Complete card checkout, address inputs, and confirmation order routing.
  • **BFF API Contract Checking**: JSON payloads validated against strict schemas (Ajv) dynamically.
  • **Boundary Values**: Rejecting integer overflow/underflow quantitive operations.

🔴 Deliberate Manual Scope (15%)

High-maintenance or infrastructure verification flows are bypassed to reduce suite fragility:

  • **External Gateway Authorization**: Live sandbox credit card processing (bypassed with validation mock stubs).
  • **Jaeger span telemetry UI validation**: Verifying spans render correctly inside Jaeger dashboard pages.
  • **Chaos resilience**: Kafka message drops or container packet losses under network partition failures.

Test Data & Flakiness Architecture

Ensuring deterministic execution environments by isolating state data and quarantining fragile tests.

Data Isolation & Flakiness Workflow

📦 State Isolation Strategy

Running parallel playwright workers threatens state stability when sharing carts. We mitigate this by generating a unique session string dynamically per test thread:

sessionId = `session-\${Math.random().toString(36).substring(2, 15)}`;

This isolates database Valkey writes cleanly without cross-thread cart conflicts.

⚠️ Flaky Test Index & Quarantine

Flaky tests degrade confidence in CI pipelines. We enforce a strict **Flaky Test Index SLA (< 1%)**:

  • **Quarantine Gate**: Any test that exhibits flakiness is dynamically tagged and isolated from blocking release pipelines.
  • **Developer Notification**: The owning service team is automatically alerted.
  • **Resolution Window**: Quarantined tests must be repaired within **48 hours**, or they are deleted from the repository.

1. Tooling Selection & Rationale

Why Playwright (TypeScript) is selected as our core testing engine for the Astronomy Shop microservices.

Our polyglot application ecosystem incorporates services written in Go, C#, C++, Java, Node.js, PHP, and Ruby. Evaluating an automation framework requires lookups beyond simple browser scripts: we require unified REST/gRPC client integrations alongside robust rendering execution. Playwright provides native advantages over traditional runners.

Criteria Playwright (TS) Cypress (JS) Selenium (Java/Python) Pytest (Python)
API & UI in One Engine Supported (Native) Limited (In-Browser) No (Requires libs) No (Requires wrappers)
Execution Speed Native Headless (Fast) Moderate (In-Browser) Slow (HTTP driver overhead) Fast (For APIs only)
Trace Viewer Yes (Full DOM, Network) Yes (DOM snapshots only) No (Requires third-party) No (Raw logs only)
Async Handling Auto-waiting (Promises) Internal Sync Queue Manual Explicit Waits Manual Polling Loops
💡 Technical Rationale Highlight
Playwright interacts directly with browser debugging protocols (CDP/WDP) over a single websocket socket connection. This bypasses the network overhead of Selenium's HTTP-to-driver translation layer, while allowing us to bypass Cypress's internal proxy constraints, enabling dynamic cross-domain API injections in our microservices tests.

Key Playwright Capabilities

⚡ Headless Speed

Direct process orchestration allows parallel headless browsers to load and execute in isolated threads with minimal memory leaks.

🔍 built-in Trace Viewer

Enables full post-execution debugging, capturing execution timelines, DOM snapshots, network payloads, and console streams.

🔄 Auto-waiting

Native locator assertions wait automatically for elements to be attached, visible, stable, and clickable, resolving classic asynchronous delays.

Codebase Architectural Standards

1. Page Object Model (POM) for UI

▶
Exposes selectors as typed properties targeting static test locators (`data-testid`), and hides actions in async methods. 
export class CheckoutPage {
  private readonly payButton = this.page.locator('[data-testid="pay-button"]');
  async submitPayment() {
    await this.payButton.click();
  }
}

2. API Client Abstractions for Backend Specs

▶
Keeps API calls clean and decoupled from test scripts. Isolates gRPC / REST network client configurations into dedicated wrapper classes. 
export class CartClient {
  async addProduct(userId: string, productId: string) {
    return await this.request.post(`/api/cart/${userId}`, { productId });
  }
}

3. Modular Custom Fixtures

▶
Automatically injects preset data, tokens, and active browser sessions into test blocks, removing code repetition inside hooks. 
test('User Checkout', async ({ authenticatedCart, checkoutPage }) => {
  await checkoutPage.navigateTo();
  await checkoutPage.submitPayment();
});

3. CI/CD Pipeline Orchestration

Continuous Integration Quality Gates executing on GitHub Actions / GitLab CI with defined execution triggers and SLAs.

Pipeline Execution Stages

Stage 1: Pre-Commit (Local Dev) SLA: < 10 Seconds
Triggers locally on Git commit via Husky. Runs code formatting tests, lint checks (ESLint), and Protobuf definition checks (`buf lint`).
Stage 2: PR Build Gate SLA: < 5 Minutes
Triggers on Pull Request creation. Compiles modified containers, executes unit suites, gRPC contract validations, and critical UI path smoke tests.
Stage 3: Merge to Main SLA: < 15 Minutes
Triggers on push or merge events to the main branch. Deploys to staging sandbox. Executes full API regressions and service boundary checks.
Stage 4: Nightly Runs SLA: < 1 Hour
Triggers at 2:00 AM UTC. Runs full cross-browser matrices, pixel-diff visual tests, security dependency scans, and performance load tests (k6).

Failure Signal Integration & Alerts

💬 Slack & Teams Webhooks

Automated notifications flag failures in real-time, detailing the failing test name, author, logs, and embedding direct links to the Playwright Trace Viewer artifact hosted on AWS S3.

✍️ GitHub PR Annotations

Test assertions annotate failing code directly on the PR source code diff. Lines triggering errors present stack traces instantly, keeping developers within their Git workflow.

🎟️ JIRA Ticket Auto-Creation

Nightly failures lingering unfixed for 4 hours automatically trigger JIRA issue generation, assigning triage tickets to the responsible domain pod leads.

📌 No Shared Global Databases
Tests must run completely stateless. Generating unique user models and active carts using backend endpoints prevents database contention, race conditions, and test pipeline lockouts.

Data Isolation Columns

🔑 UUID Account Setup

Runtime test runs automatically spin up isolated UUID users (`test_user_7b89...`). Each user is dedicated to a single test block and deleted immediately upon teardown.

🧩 Atomic Data Fixtures

Static payload schemas are kept immutable in the repository. The runner merges dynamic attributes into these JSON templates at runtime to guarantee contract validity.

🧹 Cache Key Flushing

Between test runs, playbooks trigger custom endpoints to purge specific Valkey database partitions, ensuring next runs begin with zero cached state leakage.

5. Flakiness Management & SLA Guardrails

Enforcing zero-tolerance guidelines and tracking the Flaky Test Index (FTI) to keep CI pipelines green.

Flakiness Action Rules

We implement three concrete guidelines to address flaky execution:

  • Native Auto-Waiting: Zero hardcoded sleeps (`page.waitForTimeout()`). Tests must wait on dynamic element visibility transitions.
  • CI-Only Retry Budgets: 0 retries permitted locally during development. Maximum of 2 retries allowed in CI to bypass intermittent pipeline networks.
  • Automatic `@flaky` Quarantine: Flaking tests are immediately demoted to parallel non-blocking paths, preventing pipeline blocks.

⚠️ Quarantined Triage SLA
Any test whose Flaky Test Index exceeds 2% over a 7-day period is automatically demoted from the CI blocking gate. The assigned owner must triage and fix the test within 48 hours; otherwise, the test is completely disabled until it passes 50 consecutive runs.
